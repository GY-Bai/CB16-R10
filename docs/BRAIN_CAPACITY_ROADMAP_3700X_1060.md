# Central Brain 容量发展规划：3700X / GTX 1060 6GB

日期：2026-09-12。性质：面向未来的容量评估与实验建议，不是模型晋升决定或新的训练 authority。**状态更新：CC R11 integration 已通过 PR #99 合入 `main`；本文后续容量实验必须以当前 integration receipt/spec 为运行 authority。本文本身仍不授权扩容、训练、FINAL 或 fresh data。**

## 1. 结论先行

后续导航：实际容量研究按 [后 CC 科学计划 R0](POST_CC_SCIENTIFIC_PROGRAM_R0.md) 的条件性 S4 进入；先完成实际可学习性和历史小规模诊断。本页参数区间不代表应立即跑完整网格。经济排序与沙盒晋升按 [当前定义](ECONOMIC_ORDERING_AND_PROMOTION.md)，不再悬置基准主次。

**16K 不是这台机器的参数上限。建议把决策 Brain 的主要探索范围放在 100K–5M 个可训练参数，先验证 100K–1M；5M–20M 属于有条件扩展。** 这些是根据资源预算和任务结构提出的工程判断，不是由某篇论文证明的交易最优规模。

| 决策 Brain 可训练参数 | 在本机上的规划地位 | 进入条件 |
|---|---|---|
| 约 16K–100K | 基线、闭环验证、小容量对照 | 先证明 Account 反馈、长期后果学习和科学裁判确实工作 |
| 100K–1M | 第一优先探索区 | 相同语义与预算下验证容量是否改善学习，而不只是提高拟合度 |
| 1M–5M | 后续主力候选区 | 小模型出现可信的容量不足迹象，吞吐和完整比较仍可负担 |
| 5M–20M | 有条件的扩展区 | 前面的容量曲线仍改善，且序列、器官与学习器联合实测通过 |
| 20M–50M | 不排除短序列、小批量配置能运行；不作为默认路线 | 必须有端到端性能证据，不能只展示模型成功放入显存 |
| 超过 50M，尤其 100M 及以上 | 当前主机不建议作为常规研究目标 | 不是绝对装不下，而是尚无证据表明训练周转成本值得 |

本表的参数只指承担动作决策的可训练网络。独立 Critic 另计，可先研究约 250K–5M；这同样是候选区间，不是要求 Critic 至少这么大。冻结市场器官、行为策略副本、target 网络另列资源账。不要通过更改计数口径宣称模型升级。

目前不能给出一个与架构无关的“最大可训练参数数”：同为 5M，逐步 MLP、长序列 GRU、长窗口 Transformer 的激活内存和训练吞吐可能很不同。

## 2. 输入事实与证据边界

用户本次明确的硬件为 Ryzen 7 3700X、GTX 1060 6GB、16GB 主存、小 SSD 与 1TB HDD；行情是十种主流资产的 **一分钟 K 线**，从 2020 年至 2026 年 8 月末。当前 Brain 约 16K 是用户提供的近似值，本次没有取得对应生产 checkpoint 的完整参数清单。

只为估算规模，假设十资产均为全天候交易且完整覆盖 UTC 区间 `[2020-01-01, 2026-09-01)`：

- 2,435 天；每资产 3,506,400 根分钟 bar。
- 十资产合计 35,064,000 行，约 3,506 万行。
- 实际数量须由数据 manifest 核验；不同上市时间、缺失、停牌或不同起点都会改变它。
- 一分钟原始行情、模型决策频率、器官窗口、梯度序列长度是不同口径，不能互相替代。

**上述时间范围只描述用户持有的数据，不把全部日期自动授权为 TRAIN。** 现有 FINAL/fresh-data 防火墙和版本化数据权限不变。本文不读取新的行情、不扩大可消费范围。

## 3. 先把“16K”定义准确

未来每个容量报告至少同时列出：

| 计数项 | 含义 |
|---|---|
| `P_actor_trainable` | 决策网络实际接收梯度的唯一参数数，包括属于 Brain 的 trainable stems/heads |
| `P_critic_trainable` | 独立价值网络实际接收梯度的唯一参数数 |
| `P_frozen` | 冻结器官及冻结投影参数数，不计入可训练 Brain |
| `P_replica` | 另驻留的行为策略、target 或其他副本；不是新增学习能力 |
| 结构与运行配置 | 隐藏宽度、深度、记忆形式、序列长度、batch、精度、优化器、运行设备 |

[CCCentralBrain 源码](https://github.com/GY-Bai/CB16-R10/blob/fc7adaae66da5b7735a3ab6aee7a8c7bd3721ed2/cb16_local_opt/cc_policy_brain_r0.py) 中，设市场维度为 M、账户维度 A、执行维度 E、隐藏宽度 H，则该类自身：

```text
可训练参数 = 2H² + H(A + E + 8) + 9
冻结线性市场投影参数 = MH
类内总参数 = 2H² + H(M + A + E + 8) + 9
```

这是针对该 SHA 中具体层定义的静态推导，不包含类外预训练器官。对应单测只是微型尺寸测试，并不能确认真实部署使用的 M/A/E/H；也不能据这个冻结线性层认定完整预训练器官已接入。因此本文不把“约 16K”冒充精确核验结果，不拿历史 R10 网络计数替换当前口径。

## 4. 显存预算：百万级权重本身并不大

按 FP32 计算，每参数权重 4 字节、梯度 4 字节；普通 Adam 的两个状态合计再加 8 字节，即固定训练状态约 **16 字节/可训练参数**。还须另加激活、临时张量、工作区和其他驻留对象；Adam foreach 路径还可能增加约一份参数大小的峰值临时内存。[PyTorch 内存分解](https://docs.pytorch.org/tutorials/intermediate/optimizer_step_in_backward_tutorial.html)、[Adam 文档](https://docs.pytorch.org/docs/main/generated/torch.optim.Adam.html)。

下表是假设 Actor/Critic 均为 FP32、均用普通 Adam、没有共享参数时的解析预算，**不是当前 runner 的测量**。1 MiB = 2²⁰ 字节；1M 参数 = 1,000,000 参数。

| Actor 参数 | Actor 权重 MiB | Actor 权重+梯度+Adam 状态 MiB | 加上同等大小 Critic 后的固定训练状态 MiB |
|---|---:|---:|---:|
| 16K | 0.06 | 0.24 | 0.49 |
| 100K | 0.38 | 1.53 | 3.05 |
| 1M | 3.81 | 15.26 | 30.52 |
| 5M | 19.07 | 76.29 | 152.59 |
| 10M | 38.15 | 152.59 | 305.18 |
| 50M | 190.73 | 762.94 | 1,525.88 |
| 100M | 381.47 | 1,525.88 | 3,051.76 |

所以，1M Actor + 1M Critic 的这部分开销只有约 30.5 MiB，不能据 6GB 显存就把 Brain 限定为 16K；反过来，100M 两网络的固定状态约 3GiB，也不能据此宣称完整训练能塞进 6GB。

实用预算式为：

```text
显存峰值 ≈ 16 × (P_actor_trainable + P_critic_trainable)
         + 4 × (P_frozen_GPU + P_replica_GPU)
         + 激活(batch、序列长度、宽度、深度、算法)
         + 临时张量、CUDA/cuDNN 工作区、缓存与运行时开销
```

共享参数只计一次，实际精度和优化器必须替换进公式。[CC learner](https://github.com/GY-Bai/CB16-R10/blob/fc7adaae66da5b7735a3ab6aee7a8c7bd3721ed2/cb16_local_opt/cc_learner_r0.py) 使用无 momentum 的 SGD，不是 Adam；其权重加梯度的基础预算约 8 字节/参数。此处使用 Adam 只是为未来保留较宽预算，不授权切换优化器。

必须在预热、实际 forward/backward、优化器状态建立之后测峰值，并把采样侧与学习侧的同时驻留纳入测试。可用显存以运行时测量为准，不把标称 6GB 全部分配给模型。混合精度不能预设为 1060 的提速保证。

## 5. 更可能限制规模的是周转速度

分钟行情不会要求模型一次吞下六年序列，却会增加交互步数。同一行情上反复生成不同账户路径，进一步放大计算量；反复复习已有经历又增加 learner 工作量。

仅作工作量换算：假设每分钟决策、每资产一条完整账户路径，需要约 3,506 万次决策。若实际完整交互吞吐是 100、1,000、10,000 步/秒，对应约 97.4、9.74、0.974 小时。**这些速率是示例，不是本机预测；也没有包括额外回放学习。** 每个资产若有 K 条同长度路径，交互量近似再乘 K；提前真实终止与不同路径长度应据实累计。

对以稠密矩阵运算为主的逐步网络，可用每状态 forward 约 `2P` FLOPs、forward+backward 约 `6P` FLOPs 作量级估算。实际 GRU 门、归一化、批处理、器官和环境开销另计；不要把 FLOPs 除以显卡宣传峰值，直接宣称实验耗时。

本机优先关注：

- 多账户组成推理批次、CPU 环境与 GPU 推理有效衔接；不能在一个账户内并行执行依赖尚未发生后果的后续动作。
- 冻结且因果、确定的 Market 器官输出可按市场位置共享缓存，需绑定数据、器官与归一化版本；Account、动作结果和策略记忆不能按市场时间错误共享。
- 若每行情行缓存 96 个 FP32 特征，理论全量约 12.54GiB，已逼近 16GB 主存，尚未计系统、经验、Python 和 learner。应分片读取、控制驻留集，不为每个 worker 复制全量缓存。
- SSD 用于可容纳的热分片与活跃训练数据；HDD 适合顺序归档。SSD 实际空闲容量未知，本文不承诺全量热缓存可容纳。
- 参数变大后先定位是 GPU 计算、CPU 环境、IPC、重算器官还是 IO 等待。把 Python 改成 Rust/Go 不会直接减少 GPU 矩阵计算量。

性能运行拓扑服从当前 integration receipt/spec 与 [当前性能策略](PERFORMANCE_STRATEGY_3700X_1060.md)。本文不恢复旧 broker/farm/vectorized runtime fallback；历史 [CC 执行决策](CC_PARALLEL_EXECUTION_DECISION.md) 与 [Thread D](cc/CC_THREAD_D_PERFORMANCE_HARD_CUTOVER.md) 作为 provenance 使用。

## 6. 业务需求决定该扩大哪里

本项目学习的是 `Market + Account + 必要因果历史 → Action → Account 后果`，不是把 3,506 万行行情做成静态预测题。数据行数不能直接推出“应当多少参数”，重复账户分叉也不等于增加了同样数量的独立市场环境。

### 6.1 宽度不足与记忆不足不是同一个问题

如果已有观察已足以区分决策处境，可先扩展当前 Brain 的 trainable stems、融合网络与头部，形成可解释的容量阶梯。不能仅因参数少就直接判定它必然学不会。

如果相同简化观察掩盖了影响未来的不同历史，那么放大无记忆网络不一定解决信息缺失。应先审查观察的充分性，再把因果 GRU 等有限状态记忆作为单独候选；不能用未来行情或完整未来账户补输入。

作为结构量级示例，单层、单向、有 bias 的 GRU，输入维度 D、隐藏宽度 H，仅 GRU 主体参数为 `3H(D+H+2)`。假设 D=102 时：H=128 约 89K，H=256 约 276K，H=512 约 946K；还需加 stems/heads。这不是新 CC 输入合同，也不是要求换成 GRU。[PyTorch GRU 参数形状](https://docs.pytorch.org/docs/2.13/generated/torch.nn.GRU.html)。

账户可以跨年持续，梯度图不必跨年保留；有限梯度块不等于重置账户或删除长期后果。若使用截断反向传播，应明确它对长距离归因的限制，并验证状态传递、回放时历史重建/预热及价值估计，不能声称 GRU 自动解决无限信用分配。

冻结器官若丢失任务所需信息，更大的 Brain 不能凭空恢复它。器官充分性检验与 Brain 容量实验应分开，不以本文件授权解冻器官。

### 6.2 Actor 和 Critic 分开研究

Actor 决定方向与风险请求；Critic 估计这些账户处境下的后续经济价值。若主要误差来自长期后果估计，可以先扩大 Critic，再看 Actor 是否需要扩大；若策略拟合受限而 Critic 已可靠，则相反。

BRO 在其连续控制基准上发现，经适当正则化的大 Critic 有益，扩大 Actor 未见同样收益；其默认 Critic 约 5M。这支持“分别检验”的研究方法，不证明 CB16 应用 5M Critic，更不证明交易收益会随参数单调增加。其环境、网络和训练配方不同，不能照搬其其他机制来改动本项目目标。[Bigger, Regularized, Optimistic](https://arxiv.org/html/2405.16158v3)。

## 7. 建议的容量晋升规则

这部分是供后续实施者拆解的提案，不是立即启动的实验配置。

1. **建立真实基线。** 记录实际 checkpoint、唯一可训练参数数、梯度归属、观察/动作接口、优化器和完整运行配置；以当前 canonical CC 的 known-answer / closed-loop authority 为起点。
2. **先筛小阶梯。** 可用约 `16K → 64K → 256K → 1M → 4M` 作为 Actor 候选；结构取整后的真实计数应如实报告。不是要求一次跑完，更不是保证每档胜出。
3. **分离变量。** 固定 Actor 比较 Critic 容量；固定 Critic 比较 Actor 容量。记忆结构变化另设对照，避免把增加历史信息、改奖励和加参数同时发生的收益归为容量收益。
4. **区分两种公平预算。** 等环境交互/学习数据预算回答样本效率；等墙钟/总计算预算回答本机实用效率。固定 batch 后的 update 次数并不能跨不同 batch 代表相同训练量。主比较口径及调参预算事先声明。
5. **始终保留完整账户后果。** 相同配对市场与初始账户条件用于比较；运行后账户可因动作不同而分化。不得用 flat 重置、删掉失败、缩短后果期换吞吐。旧经验可反复学习，新策略继续产生新路径。
6. **同时给科学和性能结论。** 报告账户总体经济结果、失败与尾部、Critic 误差、策略行为、吞吐、峰值显存/主存、IO 等待和单轮总耗时。损失下降或 GPU 满载不是经济 PASS。
7. **匹配结论范围。** 在反复练习的市场改善，是合法的沙盒学习证据；若声称未见时期能力，须另有合规且未用于选择的证据。多随机种子与配对重复不能把同一市场变成许多独立市场。
8. **按成本收益停。** 若扩容改善未能稳定复现，或代价挤掉必要的账户覆盖与重复验证，保持较小模型并诊断信号/表示/归因；不能靠改排行榜、分母或收益目标挽救结果。稀有暴赚主导均值而证据不足时报告不确定，不把有限样本赢家视为已知更高期望。

用户已确认的目标保持不变：完整计入成功、普通、失败与终态后的长期算术期望超额收益。更大模型不自动获得低风险偏好；本文不增加 Sharpe、对数财富或存活优先的主排序。详见 [最高理念](VISION.md)、[学习规则](LEARNING_CONTRACT.md)、[评价原则](EVALUATION_PRINCIPLES.md)。

## 8. 软件栈与硬件决策

GTX 1060 的 CUDA compute capability 为 6.1；CUDA 13.0 已移除 Pascal 的离线编译和库支持，不能不经验证就把它迁移到最新 CUDA/PyTorch 组合。应保留已通过本机测试的兼容构建，并核验其实际包含的 GPU 架构支持，而不是仅检查 CUDA 版本号。[NVIDIA legacy GPU 清单](https://developer.nvidia.com/cuda-legacy-gpus)、[CUDA 13.0 release notes](https://docs.nvidia.com/cuda/archive/13.0.0/cuda-toolkit-release-notes/)。

仅为把约 16K 升到几十万或一百万参数，目前没有足够理由先买显卡。若实测主要卡在内存/IO，应处理缓存、驻留集与存储；若 GPU 计算已占主导，扩大 CPU worker 或改写宿主语言不会无限提速。显卡升级应由稳定的容量收益和性能证据触发，不由参数数字本身触发。

## 9. 交给后续实施者的一句话

**现在已有 synthetic closed-loop/known-answer + Shanxi performance-qualified 的 canonical CC runtime；容量研究应在这个基线上，以 Actor/Critic 分开的阶梯研究 100K–5M 级决策 Brain，并继续保持完整账户经历、失败记账、因果输入和 evidence 分层。分钟行情行数不是模型规模公式，模型变大也不是经济能力已经提升。**

尚需通过未来容量实验补齐而非本文件臆测的内容：真实当前 Brain 精确计数、实际冻结器官规模与驻留设备、具体 batch/序列、容量变化后的联合峰值与吞吐、SSD 热缓存可用空间，以及不同容量在固定科学预算下是否真的改善 known-answer / economic target。这些结果会收窄或改变本文件的实用区间。
