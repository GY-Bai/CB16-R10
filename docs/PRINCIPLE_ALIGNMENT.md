# 最高理念对齐规则

日期：2026-09-12。本文把用户已确认目标转成可审阅的行为要求；不替代运行 authority，也不因为实现完成而自动提升科学证据。

**当前状态更新：** AC/BC/CC 四线程均已成为历史实施 provenance；CC R11 integration 已通过 PR #99 合入 `main`。当前实现/运行 authority 以 `CB16_R11_CC_INTEGRATION_SPEC_V1.json`、`CB16_R11_CC_INTEGRATION_RECEIPT_V1.json`、`CURRENT_STATE.md` 为准。

## 1. 当前阅读与使用方式

新 Agent 不再从 AC TODO 或 CC 四线程 TODO 作为“待实施清单”开始。推荐顺序：

1. `CURRENT_STATE.md`
2. `CC_INTEGRATION_HANDOFF.md`
3. integration spec / receipt
4. 本页与 `COMPONENT_REQUIREMENTS.md`
5. 再按具体新任务读取算法、历史 TODO、Stage-4、performance 或 capacity 文档。

AC/BC/CC task numbering 现在主要用于历史追溯；未来新任务如需改变 science semantics，应创建新的版本化任务/authority，而不是在旧编号上静默改义。

每项结论应标明身份：

| 身份 | 可表达的内容 | 变更方式 |
|---|---|---|
| 用户已确认目标 | Trader 职责、连续账户、允许失败学习、期望收益偏好 | 用户明确后续修订，并记录替代范围 |
| 从目标推导的行为要求 | 不免费补资、不丢终态、后果进入下一次决策 | 解释其保护的目标；可提出等价实现 |
| 算法/工程候选 | V-trace、网络结构、超参数、采样比例、容量 | 在已授权任务内版本化设计与验证，不称为最高理念 |
| 实现和运行事实 | 某 SHA 的接口、某 run 的产物及结论 | 用精确代码、receipt 和 run evidence 更新，不靠计划推定完成 |

旧冻结协议限定历史运行语义，不否决用户的新目标；新目标也不追溯改写历史结果。发现冲突，指出具体行为、适用版本和迁移路径。

## 2. 理念与可观察要求

| ID | 已确认目标 | 从目标推导的要求 | 常见偏离 |
|---|---|---|---|
| P-01 | 单资产账户 Trader | 人指定资产和资本；策略结合市场、账户及必要历史行动；执行层掌握真实合约规格 | 做成宏观配置器，或仅预测市场涨跌 |
| P-02 | 经验通过交互产生 | 每次政策决策读取实际接续账户；轨迹保留名义动作、许可、成交和后果 | 首步由模型决定，其余固定续行，却称自主连续交易 |
| P-03 | 可以反复练习 | 已有经验可重复学习；新政策持续产生新的合法账户路径 | 将静态测试集不断换新当成学习本身，或声称可穷尽连续状态空间 |
| P-04 | 账户长期承担后果 | 计算切片、暂停恢复与换代均不得隐形重置本金或持仓 | 把 72h、batch、文件末尾当账户自然死亡 |
| P-05 | 风险取舍由模型学习 | 开仓、持仓调整和退出有明确行动空间；外部限制说明来源 | 人工止损、固定持有时间或模型偏好被藏进执行器 |
| P-06 | 完整计入失败后的长期期望收益 | 目标保持算术期望取向；比较明确人群、资本、权重、时域及基准 | 自动改用 Sharpe、对数效用、存活率或冠军单轨迹 |
| P-07 | 成功失败完整保留，优胜示范另筛 | 事实记录、训练抽样和示范筛选分开；终态损失进入后果学习 | 删除爆仓，或把失败轨迹每一步统一标为错误 |
| P-08 | 冻结器官，训练 Central Brain | 冻结市场器官与可训练融合/账户 stems 区分；审阅真实梯度归属 | 因“encoder 冻结”把账户处理和 Brain 也冻结 |
| P-09 | 固定运行 checkpoint，分代进化 | 学习在副本进行，切换留来源并接续账户；历史可复习，新经验可校准 | 运行中偷偷更新权重，或按时间永久清除历史模式 |
| P-10 | 根据可信证据判断进展 | 分别报告接线、优化、经济改善与迁移证据 | 将 workflow success 或 loss 下降写成学会交易 |

这些要求不规定必须使用某个神经网络。某个算法不适合时可以替换，但不能通过改变用户胜负标准让它通过。

## 3. 对几个容易误读的词作固定解释

**“训练场就是验证场”**：同一历史环境允许练习、复盘和观察学习效果。它不自动证明对未见时期有效；也不要求为了所谓测试纯洁性而禁止复习。先说本次验证的问题，再决定所需证据。

**“背诵整个样本空间”**：允许充分拟合已有经验，并让交互扩展可达账户覆盖；不是承诺枚举连续动作与全部账户历史。已有样本拟合、账户路径探索、未来迁移是三个不同问题。

**“Account 是核心”**：账户差异必须实际进入决策并可被学习，不意味着每两个不同账户都必须输出不同动作。只在已知最优动作依赖账户的受控例子中检验必要敏感性；无条件强迫不同动作会引入人工目标。

**“模型不需要知道资产和多少钱”**：避免把资产名称或绝对资金身份作为捷径；保留真实影响可行动作、成本和清算的可比信息。按比例缩放不保证在最小订单、固定费用或容量变化时完全等价。

**“无穷长”**：账户可跨计算任务持续；已观察历史仍有限。持续账本不等于长期信用已经正确分配，也不定义无限期终值数学极限。有限观察终点不必强制平仓。

**“让风险自己学”**：模型承担策略选择，环境负责真实后果；不是关闭保证金和清算，也不是由人工风险偏好替模型选择。风险诊断可以显示尾部；未经用户选择不能偷偷变成主排名惩罚。

## 4. 环境机制与交易策略的边界

对每项强制行为注明来源和适用版本：

| 类型 | 例子 | 对齐要求 |
|---|---|---|
| 外部执行机制 | 成交时序、手续费、保证金、清算、合法数量、资产可交易方向 | 明确现实依据或沙盒假设，确定性执行并记账；不是模型可以绕开的规则 |
| 用户明确给定的资源/应用边界 | 单资产、分配资本、未来阶段账户权限 | 记录配置来源，不能冒称市场普遍规律 |
| 人为策略偏好 | 固定止盈止损、固定持仓期限、亏损后冷却、按回撤降低仓位 | 不作为 canonical autonomous Trader 默认机制；若保留作基线，标明受限策略实验 |
| 计算或运维边界 | job timeout、批次结束、暂停、进程失败 | 保存并接续，不当作自然清算、不抹掉损失 |

CC integration 已对 canonical path 验证：signed economics、主动持仓调整、reject/NOOP 后世界继续、generation/account continuity、无 legacy performance fallback。未来版本不能以性能或便利名义回退这些边界。

## 5. 贯穿组件的验收场景

核心验收场景仍是：

在同一合法市场前缀，从可恢复的真实账户母状态分叉；不同动作分别经过许可、成交、费用和账本更新，后续 policy 读取各自实际账户继续行动。跨计算切片、恢复与合法 checkpoint 切换后，账户继续承担各自后果。失败轨迹完整保留，不只保留胜出分支。

CC 已在 synthetic known-answer canary 中接通 policy -> execution -> account -> experience -> replay -> learner -> child checkpoint -> same account -> child policy acts，并通过 hostile/recovery 与 reference-fast equivalence。

这证明连接和受控已知答案能力，**不证明真实市场盈利或 transfer**。
