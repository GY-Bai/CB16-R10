## 2. 理念与可观察要求

| ID | 已确认目标 | 从目标推导的要求 | 常见偏离 |
|---|---|---|---|
| P-01 | 单资产账户 Trader | 人指定资产和资本；策略结合市场、账户及必要历史行动；执行层掌握真实合约规格 | 做成宏观配置器，或仅预测市场涨跌 |
| P-02 | 经验通过交互产生 | 每次政策决策读取实际接续账户；轨迹保留名义动作、许可、成交和后果 | 首步由模型决定，其余固定续行，却称自主连续交易 |
| P-03 | 可以反复练习 | 已有经验可重复学习；新政策持续产生新的合法账户路径 | 将静态测试集不断换新当成学习本身，或声称可穷尽连续状态空间 |
| P-04 | 账户长期承担后果 | 计算切片、暂停恢复与换代均不得隐形重置本金或持仓 | 把 72h、batch、文件末尾当账户自然死亡 |
| P-05 | 风险取舍由模型学习 | 开仓、持仓调整和退出有明确行动空间；外部限制说明来源 | 人工止损、固定持有时间或模型偏好被藏进执行器 |
| P-06 | 完整计入失败后的长期期望收益 | 目标保持算术期望取向；比较明确人群、资本、权重、时域及基准 | 自动改用 Sharpe、对数效用、存活率或冠军单轨迹 |
| P-07 | 成功失败完整保留，优胜示范另筛 | 事实记录、训练抽样和示范筛选分开；终态损失进入后果学习 | 删除爆仓，或把失败轨迹每一步统一标为错误 |
| P-08 | 冻结器官，训练 Central Brain | 冻结市场器官与可训练融合/账户 stems 区分；审阅真实梯度归属 | 因“encoder 冻结”把账户处理和 Brain 也冻结 |
| P-09 | 固定运行 checkpoint，分代进化 | 学习在副本进行，切换留来源并接续账户；历史可复习，新经验可校准 | 运行中偷偷更新权重，或按时间永久清除历史模式 |
| P-10 | 根据可信证据判断进展 | 分别报告接线、优化、经济改善与迁移证据 | 将 workflow success 或 loss 下降写成学会交易 |

这些要求不规定必须使用某个神经网络。某个算法不适合时可以替换，但不能通过改变用户的胜负标准让它通过。

## 3. 对几个容易误读的词作固定解释

**“训练场就是验证场”**：同一历史环境允许练习、复盘和观察学习效果。它不自动证明对未见时期有效；也不要求为了保持所谓测试纯洁性而禁止复习。先说本次验证的问题，再决定所需证据。

**“背诵整个样本空间”**：允许充分拟合已有经验，并让交互扩展可达账户覆盖；不是承诺枚举连续动作与全部账户历史。已有样本拟合、账户路径探索、未来迁移是三个不同问题。

**“Account 是核心”**：账户差异必须实际进入决策并可被学习，不意味着每两个不同账户都必须输出不同动作。只在已知最优动作依赖账户的受控例子中检验必要敏感性；无条件强迫不同动作会引入新的人工目标。

**“模型不需要知道资产和多少钱”**：避免把资产名称或绝对资金身份作为捷径；保留真实影响可行动作、成本和清算的可比信息。按比例缩放不保证在最小订单、固定费用或容量变化时完全等价。

**“无穷长”**：账户可跨计算任务持续；已观察的历史仍有限。持续账本不等于长期信用已经正确分配，也不定义无限期终值的数学极限。有限观察终点不必强制平仓。

**“让风险自己学”**：模型承担策略选择，环境负责真实后果；不是关闭保证金和清算，也不是由人工风险偏好替模型选择。风险诊断可以显示尾部；未经用户选择不能偷偷变成主排名惩罚。

## 4. 环境机制与交易策略的边界

实现者对每项强制行为注明来源和适用版本：

| 类型 | 例子 | 对齐要求 |
|---|---|---|
| 外部执行机制 | 成交时序、手续费、保证金、清算、合法数量、资产可交易方向 | 明确现实依据或沙盒假设，确定性执行并记账；不是模型可以绕开的规则 |
| 用户明确给定的资源/应用边界 | 单资产、分配资本、未来阶段的账户权限 | 记录配置来源，不能冒称市场普遍规律 |
| 人为策略偏好 | 固定止盈止损、固定持仓期限、亏损后冷却、按回撤降低仓位 | 不作为新自主 Trader 的默认机制；若保留作基线，标明受限策略实验 |
| 计算或运维边界 | job timeout、批次结束、暂停、进程失败 | 保存并接续，不当作自然清算、不抹掉损失 |

“hard authority”这个名字本身不能证明规则符合最高理念。杠杆上限、最大名义金额等参数仍需说明来源；本页不擅自选择数值，也不删除历史规则。

对齐审阅应检查闭环的实际效果：例如减仓是否因“没有新增保证金”被错误拒绝；正常暂停是否永久剥夺账户后续行动；模型要求空仓是否实际只记录了一个 FLAT 字符串。

## 5. 一个贯穿组件的验收场景

这是给 sol 编写验收的场景要求，不是已执行结果，也不规定单元测试数量。

在同一合法市场前缀，从可恢复的真实账户母状态分叉：一条路径保持已有仓位，另一条由策略请求减仓或退出。分别执行许可、成交、费用、账本更新；后续政策读取各自账户继续行动。跨一次计算切片和一次恢复后，账户仍保持各自后果。合法的新 checkpoint 接手时保留账户及必要历史，记录切换。

其中一条如最终失败，完整结果仍进入所属评价与合规后果学习；不得只保留胜出分支。训练后重新收集新政策轨迹，分别报告是否更新了权重、是否改变了实际行动、目标是否改善。这个场景证明连接与责任传递；其本身不证明市场盈利。

## 6. sol 的任务与完成说明怎样对齐

沿用现有 TODO，在任务或交付说明中补充最少的追溯信息：相关 P 编号、版本/代码范围、外部输入和输出、可观察验收、实际证据、未接通处。无需再创建一套通用审批系统或为每一行代码写新文档。

| 声明 | 至少需要的证据 |
|---|---|
| 契约存在 | 字段和语义明确，非法/矛盾组合有可观察处理 |
| 组件有效 | 受控输入产生约定输出，包括与理念相关的边界情况 |
| 闭环接通 | 实际政策调用、实际成交、账本接续、经验、更新与新代使用相互可追溯 |
| 已学会受控任务 | 预先定义的已知答案任务通过，包含延迟损失与账户差异 |
| 经济能力改善 | 固定范围、共同期限、完整失败分母下的政策比较 |
| 未见时期可迁移 | 与所声称独立性匹配的证据，不重复计算已经用于选择的时期 |

执行 agent 在已有授权内自行处理常规工程选择。只有会改变用户目标或尚未确定的科学比较含义时，才把具体问题提交理念审阅；不能用“需要对齐”反复要求用户许可已确认原则。
