# NOTE — 关于 EXP-6 的 "in-support = 0" 究竟是什么，以及它不意味着什么

本文件回应审阅者提出的三个具体质疑：(1) 支持域定义是什么；(2) 标准化是否只在训练端拟合；(3) 若所有评价点都不在支持域内，M3 的相关系数从何而来。以及 (4) 没有共同支持时机制能否被识别。

---

## 1. 支持域的精确定义（代码原文）

`h517_mechanism.py` 第 92–99 行：

```python
rs = np.random.default_rng(20260911 + 31 * i + j)
n_tr = len(tr_x)
sub = rs.choice(n_tr, size=min(k_support, n_tr), replace=False)   # k_support = 200
nn = NearestNeighbors(n_neighbors=1).fit(tr_x[sub])
d_eval, _ = nn.kneighbors(ev_x)          # 每个评价行 -> 训练子样本的最近邻距离
d_train_ref, _ = nn.kneighbors(tr_x[sub])  # 每个训练点 -> 其余训练点的最近邻距离
thr = float(np.quantile(d_train_ref, 0.95))
in_support = d_eval.reshape(-1, 6) < thr
```

即：

| 项目 | 实际做法 |
|---|---|
| 度量 | **欧氏最近邻距离**（原始 102 维，未标准化） |
| 不是 | ❌ 凸包 ❌ 马氏距离 ❌ 逐维范围 ❌ 密度估计 |
| 阈值 | 训练子样本**自身**最近邻距离的 **95 分位** |
| 标准化 | **完全没有做任何标准化**（代码里没有任何 scaler、没有 train-only 拟合的均值/方差） |
| 子样本 | 每个单元从训练块随机抽 ≤200 行（固定种子 `20260911 + 31*i + j`） |

### 这个定义的两个已知缺陷（审阅者指出，我确认成立）

1. **高维下同分布新样本也可能全部落在阈值外。** 这是高维外推的凸包悖论（convex hull / typical-set 问题）。训练点到彼此的最近邻距离本身已经很大（102 维、约 1700 行），阈值随之被抬高；一个新抽取的同分布样本点，其到训练集的最近邻距离并不一定小于该阈值。**本实验没有做这个对照**（没有测"同一时期独立留出样本"的覆盖率）。
2. **95 分位是一个极端值标准，不是"有重叠"的判断标准。** 它问的是"这个评价点是否比 95% 的训练自距离都更接近训练集"——这是一个非常苛刻的问题。

### 因此，"in-support = 0.0000" 的**唯一**可靠读法

> 按这个保守标准，块间**没有可检测的最近邻重叠**。

**不能**读作：
- ❌ "泛化失败已被证明"
- ❌ "数据生成过程决定了走不通"
- ❌ "输入分布漂移已被证明"

## 2. M3 的相关系数实际是在哪些样本上算的（审阅者问到了要点）

`h517_mechanism.py` 第 125 行：

```python
sel = rows_in if rows_in.any() else np.ones(len(ev_flat), dtype=bool)
```

**当 in-support 掩码为空时，代码退回全行。** 由于 `in_support_fraction` 在所有 30 个单元上都是 0.0000，因此：

> **`direction_corr_insupport` 字段实际是全部 30 个评价单元的"全行"相关，不是"支持域内子集"的相关。字段名是错的。**

这一点必须记录为缺陷。但它对结论的影响是**有利**的，而非不利：

- 若真的只用"支持域内"的样本算，样本量会是 0（无法计算）
- 全行相关 **−0.0027**（16/30 为正）说明：**在全部可用的评价行上，预测与实际的居中效用组合几乎不相关**
- 该结论**不依赖**支持域定义

## 3. 机制识别能力：零重叠到底限制了什么

审阅者的判断我完全接受：

> 没有共同支持时，通常更难区分"输入分布变了"和"同样输入对应的效用关系变了"。

**零重叠 ⇒ 机制不可识别。** 本组实验能确立的与不能确立的：

| 能确立 | 不能确立 |
|---|---|
| 关系形状只有 1/30 单元可迁移（M2，全行口径） | 是输入漂移还是关系漂移 |
| 方向相关近零（M3，全行口径） | "时间不变性缺失"作为**已证实**的结论 |
| 按近邻 95 分位标准无重叠（M1） | 该"无重叠"是否只是定义/维度造成的现象 |
| 样本内/留出 = 0.066（EXP-5A） | 表示或归纳偏置是否不适合任务 |

原先报告里"失败机制已定位"应改为**"失败机制部分定位，且关键分支不可识别"**。已据此修正主报告第 6、7 节。

## 4. 若要真正判定支持重叠，需要补的对照（尚未做）

按审阅者的要求，一个可信的支持诊断至少需要：

1. **同分布对照**：把每个块自身切成"训练部分 / 留出部分"，测留出部分的 in-support 覆盖率。若同分布留出覆盖率也是 0，则说明是定义/维度问题而非漂移。
2. **关系稳定的正控**：在已知关系稳定的合成数据上，用同一支持定义，检查是否也被判为零覆盖。
3. **多种支持定义并列**：近邻距离、逐维范围（train-only 分位数）、低维子空间（如 PCA-8）上的最近邻距离。若低维下覆盖率显著上升，说明问题是维度而非漂移。
4. **标准化只在训练端拟合**：当前完全没做标准化，这本身也是一个应报告的缺陷。

这些均尚未执行，作为下一份预注册的前置检查项。
